Part 1 · Chapter 3

DDL · DML · TCL

The three pillars of SQL commands. DDL defines structure, DML manipulates data, and TCL controls transactions. Master these and you can build and manage any database.

⏱ ~30 min read
🎯 Beginner
📋 12 sections
3.1

DDL — Data Definition Language

DDL commands define and modify the structure (schema) of database objects like tables, indexes, and views.

📘 Note

DDL commands are auto-committed — they take effect immediately and cannot be rolled back in most databases (including standard HSQLDB behavior).

3.2

CREATE TABLE

When to use: To create a new table in the database.

SQL — CREATE TABLE Syntax
CREATE TABLE table_name (
    column1  datatype  constraint,
    column2  datatype  constraint,
    ...
);

Example — Create a PRODUCTS table

SQL
CREATE TABLE PRODUCTS (
    ProductID    INT             PRIMARY KEY,
    ProductName  VARCHAR(100)    NOT NULL,
    Category     VARCHAR(50)     DEFAULT 'General',
    Price        DECIMAL(10,2)   CHECK (Price >= 0),
    Stock        INT             DEFAULT 0
);
Result: PRODUCTS table is created (empty)
ProductIDProductNameCategoryPriceStock
Table created — no rows yet

3.3

ALTER TABLE

When to use: To modify an existing table — add/remove columns, change data types, add constraints.

SQL — ALTER TABLE Examples
-- Add a new column
ALTER TABLE PRODUCTS
    ADD COLUMN Description VARCHAR(500);

-- Drop (remove) a column
ALTER TABLE PRODUCTS
    DROP COLUMN Description;

-- Rename a column (HSQLDB syntax)
ALTER TABLE PRODUCTS
    ALTER COLUMN Stock RENAME TO QuantityInStock;

-- Change column data type
ALTER TABLE PRODUCTS
    ALTER COLUMN Price SET DATA TYPE DECIMAL(12,2);

-- Add a NOT NULL constraint
ALTER TABLE PRODUCTS
    ALTER COLUMN Category SET NOT NULL;
⚠️ Mistakes to Avoid
  • Trying to add a NOT NULL column to a table that already has data — existing rows will have NULL in that column → error. First add the column, then populate it, then add NOT NULL.
  • Dropping a column that is referenced by a foreign key — this will fail.
3.4

DROP TABLE

When to use: To completely delete a table — its structure AND all its data — permanently.

SQL — DROP TABLE
-- Drop a table completely
DROP TABLE PRODUCTS;

-- Safe drop: only drop if it exists
DROP TABLE IF EXISTS PRODUCTS;
🚨 Danger Zone

DROP TABLE is irreversible. All data is gone permanently. Always double-check before running this in production.

3.5

DML — Data Manipulation Language

DML commands operate on the data inside tables, not the structure.

3.6

INSERT INTO

When to use: To add new rows of data to a table.

SQL — INSERT Syntax (Single Row)
-- Insert a single row (all columns)
INSERT INTO PRODUCTS (ProductID, ProductName, Category, Price, Stock)
VALUES (1, 'Laptop', 'Electronics', 75000.00, 50);

-- Insert using DEFAULT for some columns
INSERT INTO PRODUCTS (ProductID, ProductName, Price)
VALUES (2, 'Mouse', 500.00);  -- Category gets 'General', Stock gets 0

-- Insert multiple rows at once
INSERT INTO PRODUCTS (ProductID, ProductName, Category, Price, Stock)
VALUES
    (3, 'Keyboard', 'Electronics', 1500.00, 100),
    (4, 'Desk Lamp', 'General',     800.00,  30),
    (5, 'Notebook', 'Books',        120.00,  200);
Result: PRODUCTS after all INSERTs

2MouseGeneral500.000
3KeyboardElectronics1500.00100
4Desk LampGeneral800.0030
5NotebookBooks120.00200
3.7

UPDATE

When to use: To modify existing data in one or more rows.

SQL — UPDATE
-- Update a single column for one row
UPDATE PRODUCTS
SET    Price = 72000.00
WHERE  ProductID = 1;

-- Update multiple columns at once
UPDATE PRODUCTS
SET    Price = 600.00,
       Stock = 75
WHERE  ProductID = 2;

-- Update all rows of a category (give 10% discount)
UPDATE PRODUCTS
SET    Price = Price * 0.90
WHERE  Category = 'Electronics';
Result: PRODUCTS after UPDATE (Electronics discounted 10%)
ProductIDProductNameCategoryPriceStock
1LaptopElectronics64800.0050
2MouseGeneral600.0075
3KeyboardElectronics1350.00100
4Desk LampGeneral800.0030
5NotebookBooks120.00200
🚨 Critical Warning

If you run UPDATE PRODUCTS SET Price = 0 without a WHERE clause, it updates ALL rows in the table. Always double-check your WHERE clause!

3.8

DELETE

When to use: To remove specific rows from a table.

SQL — DELETE
-- Delete a specific row
DELETE FROM PRODUCTS
WHERE ProductID = 5;

-- Delete all products with Stock = 0
DELETE FROM PRODUCTS
WHERE Stock = 0;

-- Delete ALL rows (structure stays intact)
DELETE FROM PRODUCTS;
CommandRemoves Data?Removes Structure?Rollback?

3.9

TCL — Transaction Control Language

A transaction is a sequence of SQL operations treated as a single unit. Either ALL of them succeed, or NONE of them take effect.

📘 ACID Properties
  • Atomicity: All or nothing.
  • Consistency: Database remains valid after transaction.
  • Isolation: Transactions don't interfere with each other.
  • Durability: Committed changes are permanent.
3.10

COMMIT

When to use: To permanently save all changes made in the current transaction.

SQL — COMMIT Example (Bank Transfer)
-- Transfer 5000 from Account A to Account B
UPDATE ACCOUNTS SET Balance = Balance - 5000 WHERE AccountID = 'A';
UPDATE ACCOUNTS SET Balance = Balance + 5000 WHERE AccountID = 'B';

-- If both succeeded, make it permanent:
COMMIT;
8

ROLLBACK

When to use: To undo all changes made in the current transaction, reverting the database to its last committed state.

SQL — ROLLBACK Example
-- Start updates
UPDATE ACCOUNTS SET Balance = Balance - 5000 WHERE AccountID = 'A';
-- Suppose an error occurs here (e.g. Account B doesn't exist)
-- Undo everything:
ROLLBACK;
9

SAVEPOINT

When to use: To mark a specific point within a transaction so you can partially rollback to that point instead of rolling back everything.

SQL — SAVEPOINT Example
INSERT INTO ORDERS (OrderID, CustomerID) VALUES (101, 501);
SAVEPOINT after_order;        -- Save point here

INSERT INTO ORDER_ITEMS (OrderID, ProductID, Qty) VALUES (101, 3, 2);
-- Suppose this second insert fails or we want to undo just it:
ROLLBACK TO SAVEPOINT after_order;  -- Only undoes the ORDER_ITEMS insert

COMMIT;  -- Commits just the ORDERS insert
TCL Summary
  • COMMIT — Save changes permanently.
  • ROLLBACK — Undo all uncommitted changes.
  • SAVEPOINT name — Mark a restore point within a transaction.
  • ROLLBACK TO SAVEPOINT name — Undo back to a specific savepoint.
