Keys & Constraints

Keys uniquely identify rows in a table. Constraints enforce data rules at the database level. Together they ensure data integrity and relational correctness.

2.1

Super Key

A Super Key is any column (or set of columns) that can uniquely identify a row in a table. It may contain extra/unnecessary columns.

From the EMPLOYEES table, all of the following are super keys:

  • {EmpID}
  • {SSN}
  • {Email}
  • {EmpID, EmpName} ← unique but has extra column
  • {EmpID, SSN, Email} ← unique but has extra columns
📘 Note

Super keys are the universe of unique identifiers. All other key types are specific subsets of super keys.

2.2

Candidate Key

A Candidate Key is a minimal super key — a super key with no redundant columns. Every column in a candidate key is necessary for uniqueness.

From our table, candidate keys are:

  • {EmpID} — uniquely identifies each employee
  • {SSN} — uniquely identifies each employee
  • {Email} — uniquely identifies each employee

{EmpID, EmpName} is NOT a candidate key because removing EmpName still gives uniqueness.

🔑 Key Points
  • Every table must have at least ONE candidate key.
  • Candidate keys are the minimal super keys.
  • One candidate key will be chosen as the Primary Key; the rest become Alternate Keys.
2.3

Primary Key

A Primary Key is the candidate key chosen to be the main identifier of rows in a table. It enforces two rules automatically:

  • Uniqueness: No two rows can have the same primary key value.
  • NOT NULL: Primary key columns can never be NULL.
SQL — Create table with Primary Key
CREATE TABLE EMPLOYEES (
    EmpID    VARCHAR(5)    PRIMARY KEY,
    SSN      CHAR(11)     UNIQUE,
    Email    VARCHAR(100)  UNIQUE,
    EmpName  VARCHAR(50)   NOT NULL,
    DeptID   VARCHAR(5)
);
🔑 Key Points
  • A table can have only ONE primary key (but it can span multiple columns — composite).
  • Primary key values should never change (avoid using names, phone numbers — use artificial IDs).
2.4

Alternate Key

An Alternate Key is any candidate key that was not chosen as the primary key. In our EMPLOYEES table, if EmpID is the primary key, then SSN and Email are alternate keys.

They are typically enforced using the UNIQUE constraint.

2.5

Composite Key

A Composite Key is a primary key that consists of two or more columns. The combination of these columns must be unique — individually they may not be.

SQL — Composite Primary Key
CREATE TABLE ENROLLMENT (
    StudentID  INT,
    CourseID   VARCHAR(10),
    Grade      CHAR(1),
    PRIMARY KEY (StudentID, CourseID)  -- Composite Key
);
Table: ENROLLMENT — Composite Key Example
StudentID 🔑CourseID 🔑Grade
101C01A
101C02B
102C01C

StudentID=101 appears twice and C01 appears twice, but the combination (101, C01) is unique — that's the composite key.

6

Foreign Key

A Foreign Key is a column in one table that refers to the Primary Key of another table. It enforces referential integrity — you cannot have an employee in department D99 if D99 doesn't exist in the DEPARTMENTS table.

SQL — Foreign Key
CREATE TABLE DEPARTMENTS (
    DeptID    VARCHAR(5)   PRIMARY KEY,
    DeptName  VARCHAR(50)  NOT NULL
);

CREATE TABLE EMPLOYEES (
    EmpID    VARCHAR(5)    PRIMARY KEY,
    EmpName  VARCHAR(50)   NOT NULL,
    DeptID   VARCHAR(5),
    FOREIGN KEY (DeptID) REFERENCES DEPARTMENTS(DeptID)
);
🔑 Key Points — Foreign Key
  • A foreign key value must exist in the referenced table's primary key column — or be NULL.
  • The child table (EMPLOYEES) holds the foreign key; the parent table (DEPARTMENTS) holds the primary key.
  • You cannot delete a row from the parent table if children reference it (unless you use CASCADE).
⚠️ Mistakes to Avoid
  • Trying to insert a foreign key value that doesn't exist in the parent table — this throws a constraint violation error.
  • Forgetting to create the parent table first before the child table.
B

Database Constraints

Constraints are rules enforced on table columns to maintain data accuracy and reliability.

7

NOT NULL Constraint

When to use: When a column must always have a value — you cannot leave it empty.

SQL — NOT NULL
CREATE TABLE STUDENTS (
    StudentID  INT          PRIMARY KEY,
    FirstName  VARCHAR(50)  NOT NULL,   -- Required
    LastName   VARCHAR(50)  NOT NULL,   -- Required
    MiddleName VARCHAR(50)             -- Optional (NULL allowed)
);
⚠️ Mistakes to Avoid
  • Trying to INSERT a row without providing a NOT NULL column — the database will reject it with an error.
8

UNIQUE Constraint

When to use: When a column's values must all be different — but unlike PRIMARY KEY, NULL values may be allowed (multiple NULLs can often coexist).

SQL — UNIQUE
CREATE TABLE USERS (
    UserID    INT           PRIMARY KEY,
    Email     VARCHAR(200)  UNIQUE NOT NULL,
    Phone     VARCHAR(15)   UNIQUE         -- NULL allowed, but if set, must be unique
);

9

CHECK Constraint

When to use: When you want to limit the range or type of values allowed in a column.

SQL — CHECK Constraint
CREATE TABLE PRODUCTS (
    ProductID  INT            PRIMARY KEY,
    ProductName VARCHAR(100)  NOT NULL,
    Price      DECIMAL(10,2)  CHECK (Price > 0),       -- Must be positive
    Category   VARCHAR(20)   CHECK (Category IN ('Electronics', 'Books', 'Clothing')),
    Stock      INT            CHECK (Stock >= 0)      -- Cannot be negative
);
💡 Tip

You can use any valid boolean expression in a CHECK constraint, including AND, OR, BETWEEN, and LIKE.

10

DEFAULT Constraint

When to use: When you want a column to automatically get a specific value if no value is provided during INSERT.

SQL — DEFAULT Constraint
CREATE TABLE ORDERS (
    OrderID    INT          PRIMARY KEY,
    CustomerID INT          NOT NULL,
    OrderDate  DATE         DEFAULT CURRENT_DATE,   -- Defaults to today's date
    Status     VARCHAR(20)  DEFAULT 'Pending',        -- Defaults to 'Pending'
    Discount   DECIMAL(5,2) DEFAULT 0.00             -- Defaults to 0
);

-- Insert without providing Status and Discount:
INSERT INTO ORDERS (OrderID, CustomerID) VALUES (1, 501);
Result: ORDERS table after INSERT

🔑 Constraints Summary
  • NOT NULL — Column must always have a value.
  • UNIQUE — All values in the column must be distinct.
  • PRIMARY KEY — Unique + Not Null; identifies each row.
  • FOREIGN KEY — Links to another table's primary key.
  • CHECK — Custom condition that column values must satisfy.
  • DEFAULT — Fallback value when none is provided.
