4.1

SELECT — Retrieving Data

When to use: To read/retrieve data from one or more tables.

SQL — SELECT Examples
-- Select all columns (*)
SELECT * FROM EMPLOYEES;

-- Select specific columns
SELECT EmpName, Dept, Salary FROM EMPLOYEES;

-- Use column aliases (AS) for cleaner output
SELECT
    EmpName  AS "Employee Name",
    Salary   AS "Monthly Pay",
    Dept     AS "Department"
FROM EMPLOYEES;

-- Computed column (annual salary)
SELECT
    EmpName,
    Salary,
    Salary * 12 AS AnnualSalary
FROM EMPLOYEES;
Result: Computed column query

DISTINCT — Removing Duplicates

When to use: To see only unique values in a column — removes duplicate rows from the result.

SQL — DISTINCT
-- How many unique departments exist?
SELECT DISTINCT Dept FROM EMPLOYEES;

4.4

AND / OR Logic — Brackets vs Bracket-less

This is one of the most common sources of bugs in SQL. Understanding operator precedence is critical.

📘 Operator Precedence Rule

AND is evaluated BEFORE OR, just like multiplication before addition in math.
A OR B AND C means A OR (B AND C)

Example: The Problem with No Brackets

SQL — Bracket-less (might give wrong results!)
-- INTENT: Get IT or HR employees from Mumbai
-- WRONG (no brackets):
SELECT EmpName, Dept, City
FROM   EMPLOYEES
WHERE  Dept = 'IT'   -- This is read as: IT  OR  (HR AND Mumbai)
  OR   Dept = 'HR'
 AND   City = 'Mumbai';
Result — WRONG: Returns ALL IT employees (from any city) + only Mumbai HR employees
EmpNameDeptCity
Alice JohnsonITMumbai
Carol WangITMumbai
Grace ParkITBangalore ← not Mumbai!
Henry BrownHRMumbai
SQL — With Brackets (CORRECT!)
-- CORRECT: Use brackets to group OR first
SELECT EmpName, Dept, City
FROM   EMPLOYEES
WHERE  (Dept = 'IT' OR Dept = 'HR')
  AND  City = 'Mumbai';
Result — CORRECT: IT and HR employees from Mumbai only
EmpNameDeptCity
Alice JohnsonITMumbai
Carol WangITMumbai
Henry BrownHRMumbai
🔑 Golden Rule

When mixing AND and OR — always use brackets to be explicit. Even if technically not needed, brackets make your intent clear and prevent bugs.

4.5

BETWEEN — Range Filtering

When to use: To filter rows where a column's value is within an inclusive range.

SQL — BETWEEN
-- Employees earning between 60000 and 85000 (inclusive)
SELECT EmpName, Salary
FROM   EMPLOYEES
WHERE  Salary BETWEEN 60000 AND 85000;

-- Employees who joined in 2021
SELECT EmpName, JoinDate
FROM   EMPLOYEES
WHERE  JoinDate BETWEEN '2021-01-01' AND '2021-12-31';
Result: Salary BETWEEN 60000 AND 85000

Alice Johnson85000

4.6

IN — Matching a List of Values

When to use: To filter rows where a column's value matches any value in a specified list. More concise than multiple OR conditions.

SQL — IN operator
-- Get employees from IT or Finance departments
SELECT EmpName, Dept
FROM   EMPLOYEES
WHERE  Dept IN ('IT', 'Finance');

-- NOT IN: Exclude certain cities
SELECT EmpName, City
FROM   EMPLOYEES
WHERE  City NOT IN ('Mumbai', 'Delhi');
Result: Dept IN ('IT', 'Finance')

4.7

IS NULL / IS NOT NULL

When to use: To find rows where a column has no value (NULL).

⚠️ Critical Point

You cannot use = NULL or != NULL. NULL is not a value — it's the absence of a value. Always use IS NULL or IS NOT NULL.

SQL — IS NULL / IS NOT NULL
-- Employees who have no commission (NULL)
SELECT EmpName, Commission
FROM   EMPLOYEES
WHERE  Commission IS NULL;

-- Employees who DO have a commission
SELECT EmpName, Commission
FROM   EMPLOYEES
WHERE  Commission IS NOT NULL;
Result: Commission IS NULL
EmpNameCommission
Bob SmithNULL
David KumarNULL

4.8

LIKE — Pattern Matching

When to use: To filter text data based on a pattern, not an exact value.

Wildcards

WildcardMeaningExampleMatches
%Any sequence of 0 or more charactersLIKE 'A%'Alice, Amit, A, Abc123
%End patternLIKE '%son'Alice Johnson, Mason
%AnywhereLIKE '%ar%'Carol, Martinez, Gary
_Any single characterLIKE '_ob'Bob, Rob, Job
_Fixed positionLIKE 'E0_'E01, E02, E09
SQL — LIKE with all patterns
-- Names starting with 'A'
SELECT EmpName FROM EMPLOYEES
WHERE  EmpName LIKE 'A%';

-- Names ending with 'ar'
SELECT EmpName FROM EMPLOYEES
WHERE  EmpName LIKE '%ar';

-- Names containing 'ar' anywhere
SELECT EmpName FROM EMPLOYEES
WHERE  EmpName LIKE '%ar%';

-- Names with exactly 3 characters before a space
SELECT EmpName FROM EMPLOYEES
WHERE  EmpName LIKE '___ %';  -- Three underscores then space then anything

-- NOT LIKE: Names that do NOT start with 'A'
SELECT EmpName FROM EMPLOYEES
WHERE  EmpName NOT LIKE 'A%';
Result: EmpName LIKE '%ar%' (contains 'ar')
EmpName
Carol Warg
Eva Martinez
Grarce Park
⚠️ Mistakes to Avoid
  • Using LIKE 'Alice' without wildcards — this is exactly like using = 'Alice'. Use wildcards for pattern matching.
  • Overusing %term% on large tables — it can be very slow as it prevents index use. Use full-text search for large datasets.
  • Confusing % (any chars) with _ (exactly one char).
4.9

ORDER BY — Sorting Results

When to use: To sort the result set by one or more columns. Default is ascending (ASC).

SQL — ORDER BY Examples
-- Sort by Salary high to low
SELECT EmpName, Salary
FROM   EMPLOYEES
ORDER BY Salary DESC;

-- Sort by Department ascending, then Salary descending
SELECT EmpName, Dept, Salary
FROM   EMPLOYEES
ORDER BY Dept ASC, Salary DESC;

-- Order by column position (2nd column)
SELECT EmpName, Salary
FROM   EMPLOYEES
ORDER BY 2 DESC;  -- 2nd column = Salary

-- NULLs: In HSQLDB, NULLs sort first in ASC by default
-- Use NULLS LAST to push NULLs to the end
SELECT EmpName, Commission
FROM   EMPLOYEES
ORDER BY Commission ASC NULLS LAST;
Result: ORDER BY Dept ASC, Salary DESC
EmpNameDeptSalary
Frank LeeFinance95000
David KumarFinance78000
Eva MartinezHR62000
Bob SmithHR55000
Henry BrownHR48000
Carol WangIT92000
Alice JohnsonIT85000
Grace ParkIT70000
🔑 ORDER BY Key Points
  • Multiple columns: separated by comma. Left-to-right priority.
  • Default is ASC — you can omit it.
  • ORDER BY is always the last clause in a SELECT query.
  • Execution order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
