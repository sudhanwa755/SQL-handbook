8.0

What Is a Subquery?

A subquery (also called an inner query or nested query) is a SELECT statement inside another SQL statement. The outer query is called the main query.

  • Subqueries are always enclosed in parentheses ( ).
  • The inner query executes first, its result is passed to the outer query.
  • Subqueries can appear in the WHERE, SELECT, FROM, and HAVING clauses.
8.1

Scalar Subquery — Returns ONE Value

When to use: When you need to compare a column against a single computed value, like the overall average salary.

SQL — Scalar Subquery in WHERE
-- Find employees earning more than the AVERAGE salary
SELECT EmpName, Dept, Salary
FROM   EMPLOYEES
WHERE  Salary > (
    SELECT AVG(Salary)
    FROM   EMPLOYEES
);

-- The inner query returns: 76714.28  (average)
-- The outer query then runs: WHERE Salary > 76714.28

Scalar Subquery in SELECT Clause

SQL — Subquery in SELECT
-- Show each employee's salary vs. the average
SELECT
    EmpName,
    Salary,
    (SELECT ROUND(AVG(Salary),2) FROM EMPLOYEES) AS AvgSalary,
    Salary - (SELECT AVG(Salary) FROM EMPLOYEES) AS DiffFromAvg
FROM   EMPLOYEES;

⚠️ Mistakes to Avoid
  • A scalar subquery must return exactly one row, one column. If it returns multiple rows, you'll get an error.
  • If the subquery might return NULL, handle it with NVL/COALESCE.
8.2

Multi-Row Subquery — Returns Multiple Values

When a subquery returns more than one row, you must use special operators: IN, ANY, or ALL.

Using IN

SQL — Multi-row Subquery with IN
-- Find employees who are managers (appear in ManagerID column)
SELECT EmpID, EmpName, Dept
FROM   EMPLOYEES
WHERE  EmpID IN (
    SELECT DISTINCT ManagerID
    FROM   EMPLOYEES
    WHERE  ManagerID IS NOT NULL
);
-- Inner query returns: (E03, E05, E06)
-- Outer query finds employees whose EmpID is in that list
Result: Employees who are managers

Using ANY and ALL

SQL — ANY and ALL
-- ANY: salary greater than AT LEAST ONE HR salary
SELECT EmpName, Salary
FROM   EMPLOYEES
WHERE  Salary > ANY (
    SELECT Salary FROM EMPLOYEES WHERE Dept = 'HR'
);
-- HR salaries: 55000, 62000
-- ANY: salary > 55000 (the smallest)

-- ALL: salary greater than ALL HR salaries
SELECT EmpName, Salary
FROM   EMPLOYEES
WHERE  Salary > ALL (
    SELECT Salary FROM EMPLOYEES WHERE Dept = 'HR'
);
-- ALL: salary > 62000 (the largest)

8.3

Correlated Subquery

A correlated subquery references a column from the outer query. It executes once for every row in the outer query (row-by-row execution).

An uncorrelated (non-correlated) subquery is completely independent — it runs once and its result is reused.

SQL — Correlated Subquery
-- Find employees earning MORE than the average of THEIR OWN department
SELECT
    e1.EmpName,
    e1.Dept,
    e1.Salary
FROM   EMPLOYEES e1
WHERE  e1.Salary > (
    SELECT AVG(e2.Salary)
    FROM   EMPLOYEES e2
    WHERE  e2.Dept = e1.Dept  -- ← references outer query's Dept!
);

-- For each outer row (e1), the inner query filters by e1.Dept:
-- IT rows: inner query calculates IT avg = (85000+92000+70000)/3 = 82333
-- HR rows: inner query calculates HR avg = (55000+62000)/2 = 58500
-- Finance: inner query calculates Finance avg = (78000+95000)/2 = 86500
Result: Employees earning above their dept's average
EmpNameDeptSalaryDept Avg
CarolIT9200082333 (IT Avg)
EvaHR6200058500 (HR Avg)
FrankFinance9500086500 (Finance Avg)
Correlated vs Uncorrelated
  • Uncorrelated: Inner query is independent. Runs ONCE. Faster.
  • Correlated: Inner query references outer query column. Runs for EVERY outer row. Slower but more powerful.
  • You can often rewrite a correlated subquery as a JOIN for better performance.
8.4

EXISTS and NOT EXISTS

When to use: To check whether a subquery returns any rows at all. More efficient than IN for large datasets because it stops as soon as one match is found.

EXISTS returns TRUE if the subquery returns at least one row. It ignores the actual data — only tests for existence.

SQL — EXISTS
-- Find employees who HAVE appeared as a ManagerID (i.e., they manage someone)
SELECT EmpID, EmpName, Dept
FROM   EMPLOYEES e1
WHERE  EXISTS (
    SELECT 1   -- SELECT 1 is a convention (doesn't matter what you select)
    FROM   EMPLOYEES e2
    WHERE  e2.ManagerID = e1.EmpID
);

-- NOT EXISTS: employees who manage NO ONE
SELECT EmpID, EmpName, Dept
FROM   EMPLOYEES e1
WHERE  NOT EXISTS (
    SELECT 1
    FROM   EMPLOYEES e2
    WHERE  e2.ManagerID = e1.EmpID
);

8.5

Subquery in FROM Clause (Inline View / Derived Table)

A subquery in the FROM clause creates a temporary table that the outer query can use. You must give it an alias.

SQL — Subquery in FROM
-- First compute dept averages, then filter depts with avg > 70000
SELECT
    dept_summary.Dept,
    dept_summary.AvgSalary
FROM (
    -- Inner query: compute averages per department
    SELECT
        Dept,
        ROUND(AVG(Salary), 2) AS AvgSalary,
        COUNT(*)                AS EmpCount
    FROM     EMPLOYEES
    GROUP BY Dept
) dept_summary   -- Alias is mandatory
WHERE dept_summary.AvgSalary > 70000
ORDER BY dept_summary.AvgSalary DESC;

8.6

Nested Subqueries

Subqueries can be nested inside other subqueries. This allows very complex conditions to be expressed cleanly.

SQL — Nested (Multi-level) Subquery
-- Find employees in the department with the HIGHEST total salary bill
SELECT EmpName, Dept, Salary
FROM   EMPLOYEES
WHERE  Dept = (
    -- Level 2: find which dept has the max total salary
    SELECT Dept
    FROM   EMPLOYEES
    GROUP BY Dept
    HAVING SUM(Salary) = (
        -- Level 3: what is the maximum total salary across all depts?
        SELECT MAX(DeptTotal)
        FROM (
            SELECT SUM(Salary) AS DeptTotal
            FROM EMPLOYEES
            GROUP BY Dept
        ) totals
    )
);
Result: Employees in IT (highest total salary dept = 247000)

8.7

Subquery in HAVING

SQL — Subquery in HAVING
-- Find departments whose avg salary > overall avg salary
SELECT
    Dept,
    ROUND(AVG(Salary), 2) AS DeptAvg
FROM     EMPLOYEES
GROUP BY Dept
HAVING   AVG(Salary) > (
    SELECT AVG(Salary) FROM EMPLOYEES
);
Result: Depts with avg salary above overall avg (76714)

Subquery Summary
  • Scalar: Returns one value. Use with =, >, <.
  • Multi-row: Returns many values. Use with IN, ANY, ALL.
  • Correlated: References outer query. Runs per outer row.
  • Uncorrelated: Independent. Runs once.
  • EXISTS: Tests if any row exists. Fast; handles NULL correctly.
  • Inline View: Subquery in FROM. Must have alias.
  • In HAVING: Filter groups using aggregate results from another query.
⚠️ Mistakes to Avoid
  • Using = with a multi-row subquery — this throws an error. Use IN instead.
  • Using NOT IN when the subquery might return NULLs — NOT IN (1, 2, NULL) always returns no rows! Use NOT EXISTS instead.
  • Forgetting to alias subqueries in the FROM clause.
  • Deeply nested subqueries are hard to read — consider rewriting as JOINs or Common Table Expressions (CTEs) for clarity.
