GROUP BY & HAVING

Aggregation transforms raw rows into meaningful summaries. GROUP BY organizes rows into groups, aggregate functions compute values for each group, and HAVING filters those groups. This chapter also definitively answers: WHERE vs HAVING — when to use which?

6.1

Aggregate Functions

Aggregate functions compute a single summary value from multiple rows.

FunctionWhat it doesNULL handling
COUNT(*)Counts ALL rows (including NULLs)Includes NULLs
COUNT(col)Counts rows where col is NOT NULLIgnores NULLs
SUM(col)Total sum of numeric columnIgnores NULLs
AVG(col)Average of numeric columnIgnores NULLs
MIN(col)Smallest valueIgnores NULLs
MAX(col)Largest valueIgnores NULLs
SQL — Aggregate Functions (no GROUP BY yet)
SELECT
    COUNT(*)           AS TotalEmployees,      -- 8
    COUNT(Commission)  AS WithCommission,      -- 4 (NULLs ignored)
    SUM(Salary)        AS TotalSalary,          -- 585000
    AVG(Salary)        AS AvgSalary,            -- 73125
    MIN(Salary)        AS MinSalary,            -- 48000
    MAX(Salary)        AS MaxSalary             -- 95000
FROM   EMPLOYEES;
Result: Aggregates over the whole table
TotalEmployeesWithCommissionTotalSalaryAvgSalaryMinSalaryMaxSalary
84585000731254800095000
⚠️ AVG and NULL

AVG(Commission) divides the SUM by the count of non-NULL values (4), not by total rows (8). This is often what you want — but be aware of it!

6.2

GROUP BY — Aggregating by Category

When to use: When you want to calculate aggregate values for each group/category separately.

📘 The Golden Rule of GROUP BY

Every column in your SELECT clause must either be (a) in the GROUP BY clause, or (b) wrapped in an aggregate function. Nothing else is allowed.

SQL — GROUP BY basic
-- Count employees, total salary, and avg salary per department
SELECT
    Dept,
    COUNT(*)    AS EmpCount,
    SUM(Salary) AS TotalSalary,
    AVG(Salary) AS AvgSalary,
    MAX(Salary) AS TopSalary
FROM   EMPLOYEES
GROUP BY Dept
ORDER BY SUM(Salary) DESC;

6.3

HAVING — Filtering Aggregated Groups

When to use: To filter groups after aggregation — i.e., to filter based on aggregate function results.

SQL — HAVING Clause
-- Show only departments with more than 2 employees
SELECT
    Dept,
    COUNT(*)    AS EmpCount,
    AVG(Salary) AS AvgSalary
FROM   EMPLOYEES
GROUP BY Dept
HAVING   COUNT(*) > 2;   -- Filter after grouping

-- Departments where avg salary exceeds 70000
SELECT
    Dept,
    AVG(Salary) AS AvgSalary
FROM   EMPLOYEES
GROUP BY Dept
HAVING   AVG(Salary) > 70000
ORDER BY AVG(Salary) DESC;
Result: Departments where AVG(Salary) > 70000
DeptAvgSalary
Finance86500.0
IT82333.3
6.4

WHERE vs HAVING — The Definitive Answer

FeatureWHEREHAVING
Filters Individual rows Grouped groups
When it runs Before GROUP BY (on raw rows) After GROUP BY (on grouped result)
Can use aggregate functions? NO — e.g., WHERE SUM(...) is INVALID YES — e.g., HAVING SUM(...) > 1000
Can use regular columns? YES YES (if in GROUP BY)

Execution Order of a SELECT Query

1
FROM — Which table?
2
WHERE — Filter individual rows before grouping
3
GROUP BY — Group the remaining rows
4
HAVING — Filter the groups
5
SELECT — Choose which columns to display
6
ORDER BY — Sort the final result

Example: Using WHERE + GROUP BY + HAVING Together

SQL — WHERE + GROUP BY + HAVING
-- Among IT and Finance employees (WHERE),
-- group by department,
-- and show only groups with avg salary > 80000 (HAVING)

SELECT
    Dept,
    COUNT(*)    AS EmpCount,
    AVG(Salary) AS AvgSalary,
    SUM(Salary) AS TotalSalary
FROM   EMPLOYEES
WHERE  Dept IN ('IT', 'Finance')   -- Step 2: filter rows first
GROUP BY Dept                       -- Step 3: group them
HAVING   AVG(Salary) > 80000     -- Step 4: filter groups
ORDER BY AVG(Salary) DESC;         -- Step 6: sort final result
Result: WHERE filters to IT & Finance; HAVING keeps only AvgSalary > 80000
DeptEmpCountAvgSalaryTotalSalary
Finance286500.0 ✅173000
IT382333.3 ✅247000
🔑 Simple Memory Rule
  • Use WHERE to filter on raw column values (before grouping).
  • Use HAVING to filter on aggregate results (after grouping).
  • WRONG: WHERE COUNT(*) > 2 ← Error! Can't use aggregate in WHERE.
  • CORRECT: HAVING COUNT(*) > 2
⚠️ Mistakes to Avoid
  • Using aggregate functions in WHERE — this is a syntax error.
  • Putting columns in SELECT that are neither in GROUP BY nor in an aggregate function.
  • Forgetting that WHERE runs BEFORE grouping — so it cannot see group summaries.
6.5

COUNT with DISTINCT

When to use: To count unique values in a column.

SQL — COUNT DISTINCT
-- How many unique cities are employees from?
SELECT
    COUNT(*)                 AS TotalRows,          -- 8
    COUNT(DISTINCT City)    AS UniqueCities,        -- 3
    COUNT(DISTINCT Dept)    AS UniqueDepts          -- 3
FROM   EMPLOYEES;
