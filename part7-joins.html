7.1

INNER JOIN — Matching Rows Only

What it returns: Only rows where the join condition matches in both tables. Non-matching rows from either table are excluded.

EMPLOYEES
(Left)
INNER
DEPARTMENTS

SQL — INNER JOIN
SELECT
    e.EmpID,
    e.EmpName,
    d.DeptName,
    e.Salary
FROM       EMPLOYEES   e
INNER JOIN DEPARTMENTS d  ON  e.DeptID = d.DeptID;
Result: INNER JOIN (Grace excluded — no DeptID; Marketing excluded — no employees)

7.2

LEFT JOIN (LEFT OUTER JOIN)

What it returns: All rows from the left table, plus matching rows from the right table. Where there's no match, right table columns are NULL.

SQL — LEFT JOIN
-- All employees, even those without a department
SELECT
    e.EmpID,
    e.EmpName,
    COALESCE(d.DeptName, 'No Department') AS DeptName,
    e.Salary
FROM      EMPLOYEES   e
LEFT JOIN DEPARTMENTS d  ON  e.DeptID = d.DeptID;
Result: LEFT JOIN (Grace is now included with NULL DeptName)

What it returns: All rows from the right table, plus matching rows from the left. Where there's no match, left table columns are NULL.

7.4

FULL OUTER JOIN

What it returns: All rows from both tables. Where there's no match on either side, NULLs fill the gaps.

SQL — FULL OUTER JOIN
-- All employees AND all departments
SELECT
    e.EmpID,
    e.EmpName,
    d.DeptID,
    d.DeptName
FROM            EMPLOYEES   e
FULL OUTER JOIN DEPARTMENTS d  ON  e.DeptID = d.DeptID;

7.5

CROSS JOIN — Cartesian Product

What it returns: Every row from the left table paired with every row from the right table. M × N rows total. No join condition needed.

When to use: Generate all combinations (e.g., product + size + color, days of week + shifts).

SQL — CROSS JOIN
-- Generate all dept + project combinations (4 × 4 = 16 rows)
SELECT
    d.DeptName,
    p.ProjectName
FROM       DEPARTMENTS d
CROSS JOIN PROJECTS    p;
⚠️ Warning

On large tables, CROSS JOIN creates enormous result sets. 1000 × 1000 = 1,000,000 rows. Always use intentionally.

7.6

SELF JOIN — Joining a Table to Itself

When to use: When a table has a relationship with itself — for example, employees have a ManagerID that refers to another EmpID in the same table.

SQL — SELF JOIN (Employee-Manager)
-- List each employee with their manager's name
-- Use TWO aliases for the SAME table
SELECT
    emp.EmpID,
    emp.EmpName                            AS EmployeeName,
    mgr.EmpName                            AS ManagerName
FROM      EMPLOYEES emp
LEFT JOIN EMPLOYEES mgr  ON  emp.ManagerID = mgr.EmpID;
-- LEFT JOIN ensures Carol, Eva, Frank (no manager) are still shown
Result: SELF JOIN — Employee with their Manager

🔑 Self Join Key Points
  • Always use table aliases to distinguish the two copies of the same table.
  • Use LEFT JOIN if some rows might not have a matching self-reference (e.g., top-level managers).
  • Common use cases: employee–manager, category–subcategory, city–distance matrix.
7.7

Joining 3+ Tables in One Query

You can chain as many joins as you need. Each join adds another table to the result.

SQL — 3-Table JOIN
-- Employees + their Department + Department's Projects
SELECT
    e.EmpName,
    d.DeptName,
    p.ProjectName,
    p.Budget
FROM       EMPLOYEES   e
INNER JOIN DEPARTMENTS d  ON  e.DeptID   = d.DeptID
INNER JOIN PROJECTS    p  ON  d.DeptID   = p.DeptID
ORDER BY   d.DeptName, e.EmpName;
Result: 3-table JOIN (Employees + Department + Projects)

Set Operations — UNION, INTERSECT, EXCEPT

Set operations combine the results of two SELECT queries. Both queries must return the same number of columns with compatible data types.

🔑 Join Summary
  • INNER JOIN: Only matching rows from both sides.
  • LEFT JOIN: All left rows + matching right rows (NULLs for non-matches).
  • RIGHT JOIN: All right rows + matching left rows.
  • FULL OUTER JOIN: All rows from both sides.
  • CROSS JOIN: Every combination of rows (M × N).
  • SELF JOIN: Table joined to itself using aliases.
